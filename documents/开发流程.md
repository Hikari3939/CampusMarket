# 开发流程

---

## 阶段零：项目初始化与环境搭建

*目标：跑通前后端基础框架，确保能连上数据库。*

1. **数据库准备 (MySQL)**
    * 本地安装 MySQL 8.0。
    * 执行 `mysql -u root -p < mysql_init.sql` 创建数据库和表。
2. **后端初始化 (Flask)**
    * 创建 Python 虚拟环境或使用 conda。
    * 安装依赖：`pip install -r requirements.txt`。
    * 复制 `.env.example` 为 `.env`，填写数据库密码等配置。
    * 启动：`python run.py`。
3. **前端初始化 (Vue 3)**
    * `npm install` 安装依赖。
    * `npm run dev` 启动开发服务器。
    * 检查 `.env.development` 中的 API 地址是否指向后端。

---

## 阶段一：数据库核心模型设计

*目标：构建支撑核心业务的底层数据表（SQLAlchemy ORM）。*

七张核心表：

1. **User (用户表)**: `id`, `username`, `email`, `password_hash`, `avatar_url`, `created_at`
2. **Product (商品表)**: `id`, `seller_id`, `title`, `description`, `category`, `price`, `image_url`, `status`, `created_at`, `updated_at`
3. **ProductImage (商品多图表)**: `id`, `product_id`, `image_url`, `sort_order`, `created_at`
4. **Order (订单表)**: `id`, `order_no`, `buyer_id`, `seller_id`, `product_id`, `deal_price`, `status`, `created_at`
5. **Message (私信表)**: `id`, `sender_id`, `receiver_id`, `content`, `is_read`, `created_at`
6. **Favorite (收藏表)**: `id`, `user_id`, `product_id`, `created_at` (UNIQUE user+product)
7. **Review (评价表)**: `id`, `order_id`, `reviewer_id`, `reviewee_id`, `rating`, `comment`, `created_at` (UNIQUE order+reviewer)

商品状态流转：`active` → `sold` ↔ `active`（取消订单恢复）→ `deleted`（终结态）

## 阶段二：用户认证与基础骨架

*目标：实现 JWT 鉴权闭环。*

1. **后端 API**：
    * `POST /api/auth/register`: 密码强度校验（≥6位 + 字母 + 数字），邮箱格式校验，Hash 加密存储。
    * `POST /api/auth/login`: 校验密码，签发 JWT Token（identity 使用字符串）。
2. **前端**：
    * 登录/注册 UI，含密码规则提示。
    * Pinia `userStore` 管理 Token 和用户信息。
    * Axios 请求拦截器自动注入 Token。
    * Vue Router 路由守卫拦截未登录访问。

---

## 阶段三：商品展示与管理闭环

*目标：商品的发布、分类、查看、搜索、编辑和删除。*

1. **后端 API**：
    * `POST /api/products`: 接收 FormData（含分类 `category`），支持多图 `image_0..image_4`（最多 5 张），UUID 重命名图片。
    * `GET /api/products`: 列表支持 `?keyword=` 模糊搜索 + `?category=` 分类筛选 + `?min_price=&max_price=` 价格区间 + `?page=&per_page=` 分页。
    * `GET /api/products/<id>`: 商品详情，返回 `image_urls` 多图数组。
    * `PUT /api/products/<id>`: 编辑商品（仅卖家），支持部分字段更新和多图替换。
    * `DELETE /api/products/<id>`: 软删除（仅卖家），`status` → `deleted`。
2. **前端**：
    * 首页：分类标签筛选 + 价格区间筛选 + 骨架屏加载 + IntersectionObserver 无限滚动。
    * 发布页：分类下拉选择器 + 多图上传预览（最多 5 张）+ 上传进度条。
    * 商品详情页：多图轮播（ImageGallery 组件）+ 卖家可编辑（支持多图替换）、可下架；买家可购买、可联系。
    * 商品卡片：收藏心形按钮 + 卖家迷你头像 + 点击卖家名跳转主页。

---

## 阶段四：购物与历史记录追踪

*目标：交易流水闭环 + 订单管理。*

1. **后端 API**：
    * `POST /api/orders`: 创建订单（`with_for_update()` 行级锁防超卖，禁止自买）。
    * `PUT /api/orders/<id>/cancel`: 取消订单（仅买家），订单状态 → cancelled，商品状态 → active。
    * `GET /api/users/me/published`: 我发布的商品历史。
    * `GET /api/users/me/bought`: 我购买的订单历史（含订单号、成交价、商品信息）。
2. **前端**：
    * 商品详情页：点击"立即购买"创建订单，成功后跳转个人中心。
    * 个人中心：双 Tab 展示买卖历史；"我买到的"支持取消订单（确认弹窗）。

---

## 阶段五：实时通讯

*目标：基于 WebSocket 的实时私信。*

1. **后端 (Flask-SocketIO)**：
    * JWT 握手鉴权，`online_users` 字典维护在线状态。
    * 事件：`send_message`（持久化 + 路由推送）、`receive_message`（实时推送）、`mark_as_read`（已读回执）。
2. **前端 (socket.io-client)**：
    * Pinia `chatStore` 管理连接生命周期和消息状态。
    * 聊天界面：左侧联系人列表（未读红点）+ 右侧对话框。
    * 乐观更新：消息先显示到本地，服务器确认后替换临时 ID。
    * 全局通知：非当前聊天窗口收到消息时弹窗提示。

---

## 阶段六：用户资料与公开主页

*目标：完善用户体系。*

1. **后端 API**：
    * `PUT /api/users/me`: 修改用户名和头像（支持 JSON 纯文本或 FormData 含头像文件）。
    * `PUT /api/users/me/password`: 修改密码（验证旧密码 + 新密码强度校验）。
    * `GET /api/users/<id>/profile`: 公开用户主页（用户信息含头像 + 信誉评分 + 在售商品列表）。
2. **前端**：
    * 个人中心：编辑资料按钮 → 对话框中修改用户名 / 上传头像 / 修改密码。
    * 用户主页：点击任意卖家名 → 展示头像、用户名、加入时间、信誉评分、在售商品网格、历史评价。
    * 头像展示：顶栏、聊天联系人、商品卡片、用户主页、商品详情页统一显示头像。

---

## 阶段七：收藏与心愿单

*目标：用户可以收藏感兴趣的商品。*

1. **后端 API**：
    * `POST /api/favorites`: 收藏/取消收藏（切换式）。
    * `GET /api/favorites`: 收藏列表（分页，仅展示在售商品）。
    * `GET /api/favorites/check?ids=`: 批量检查收藏状态。
    * 新增 `favorites` 表，UNIQUE(user_id, product_id) 防重复。
2. **前端**：
    * 商品卡片 + 详情页：心形按钮一键收藏/取消，红色实心/灰色空心区分状态。
    * 个人中心新增"我的收藏" Tab，展示收藏商品网格（复用 ProductCard）。
    * 乐观更新：点击即切换 UI，API 失败时回退。

---

## 阶段八：交易评价体系

*目标：订单完成后买卖双方互评，建立信誉体系。*

1. **后端 API**：
    * `POST /api/reviews`: 创建评价（1-5星 + 文字评论），验证订单完成、身份合法、未重复。
    * `GET /api/reviews/check/<order_id>`: 检查是否已评价。
    * `GET /api/users/<id>/reviews`: 获取用户收到的评价列表 + 平均评分。
    * 新增 `reviews` 表，UNIQUE(order_id, reviewer_id) 防重复。
2. **前端**：
    * StarRating 组件：5 颗可点击星星，支持交互/只读双态。
    * Profile "我买到的" Tab：已完成订单显示"评价"按钮 → 弹出评价对话框。
    * UserProfile：评价摘要（平均分 + 评价数）+ 评价列表（含评价者头像、评分、内容）。

## 阶段九：UI/UX 增强

*目标：暗色模式、多图展示、用户头像。*

1. **暗色模式**：
    * Pinia `themeStore` 管理状态，`localStorage` 持久化。
    * `html.dark` 类名切换，CSS 变量覆盖所有页面和组件。
    * 导入 Element Plus 原生暗色 CSS 变量，自动适配所有 Element 组件。
    * 顶栏切换按钮（太阳/月亮图标）。
2. **多图展示**：
    * ImageGallery 组件：单图直接展示 + 多图轮播（el-carousel）+ 灯箱预览。
    * 发布/编辑页支持最多 5 张图片上传，缩略图网格预览，可逐张删除。
3. **用户头像**：
    * 头像上传至 `static/uploads/avatars/`，更换时自动删除旧文件。
    * 全局显示：顶栏、聊天联系人、商品卡片卖家、详情页、用户主页。

## 阶段十：联调、测试与安全加固

*目标：全面测试，安全加固。*

1. **安全措施**：
    * 敏感信息 `.env` 化（数据库密码、JWT 密钥）。
    * CORS 白名单（非 `*` 通配）。
    * 统一错误信息防用户枚举。
    * 全接口越权校验（编辑/删除/取消/评价均校验身份）。
2. **功能测试**：
    * 全 22 个 API 端点的正向/异常/越权测试。
    * WebSocket 连接鉴权 + 消息收发 + 已读回执。
    * 暗色模式切换全页面无样式异常。
    * 前端构建验证（无编译错误）。
3. **数据库优化**：
    * `status` 列索引加速过滤。
    * `created_at` 列索引加速排序分页。
    * `price` 列索引加速价格区间查询。
    * `messages(sender_id, receiver_id)` 复合索引加速联系人查询。

## 重点技术指南

1. **CORS 配置**：本地开发时 Vue 和 Flask 不同端口，后端必须配置 CORS 白名单。
2. **Vue3 响应式**：Pinia store 解构时使用 `storeToRefs()` 保持响应性。
3. **图片处理**：编辑商品时先删除旧图片文件和 product_images 记录再保存新文件。头像上传同理。
4. **多图上传**：前端以 `image_0`~`image_4` 字段发送，后端 `collect_image_files()` 统一收集，保存至 `product_images` 表，`Product.to_dict()` 返回 `image_urls` 数组。
5. **订单事务**：下单操作（创建订单 + 修改商品状态）在同一事务中，异常时 rollback。
6. **评价约束**：UNIQUE(order_id, reviewer_id) 保证每人每订单只能评价一次；评价者必须是订单的买家或卖家。
7. **收藏切换**：POST 同一端点实现 toggle 效果，UNIQUE(user_id, product_id) 防重复。
8. **暗色模式**：Element Plus 原生暗色 CSS 变量 + 自定义 `html.dark` 选择器覆盖项目特定样式。主题状态由 `theme.js` Pinia store 管理。
9. **环境变量**：后端通过 `python-dotenv` 加载 `.env`；前端通过 Vite 的 `import.meta.env` 读取配置。
