# 开发流程

---

## 阶段零：项目初始化与环境搭建

*目标：跑通前后端基础框架，确保能连上数据库。*

1. **数据库准备 (MySQL)**
    * 本地安装 MySQL 8.0。
    * 创建本地数据库：`CREATE DATABASE campus_trade DEFAULT CHARACTER SET utf8mb4;`
2. **后端初始化 (Flask)**
    * 创建 Python 虚拟环境：`python -m venv venv`
    * 安装核心依赖：`Flask`, `Flask-SQLAlchemy`, `PyMySQL`, `Flask-JWT-Extended` (用于登录), `Flask-CORS` (跨域), `Flask-SocketIO` (用于实时通信)。
    * 配置应用结构（参考课件的包图）：分出 `api`, `models`, `services` 等目录。
3. **前端初始化 (Vue 3)**
    * 使用 Vite 创建项目：`npm create vue@latest`
    * 安装核心依赖：`vue-router`, `pinia`, `axios`, `socket.io-client` (实时通信前端库)，以及 UI 组件库（推荐 Element Plus 或 Vant）。

---

## 阶段一：数据库核心模型设计 (第 2-3 天)

*目标：构建支撑核心业务的底层数据表（SQLAlchemy ORM）。*

需要在 `models/` 目录下设计以下四张核心表：

1. **User (用户表)**: `id`, `username`, `email` (或学号), `password_hash`, `created_at`。
2. **Product (商品表)**: `id`, `seller_id` (外键), `title`, `description`, `price`, `image_url`, `status` (待售/已售/下架), `created_at`。
3. **Order (订单表)**: `id`, `buyer_id` (外键), `seller_id` (外键), `product_id` (外键), `status` (已下单/已完成), `created_at`。
4. **Message (私信表)**: `id`, `sender_id`, `receiver_id`, `content`, `is_read`, `created_at`。（用于存储历史聊天记录）

---

## 阶段二：用户认证与基础骨架

*目标：实现“谁在使用系统”，完成 JWT 鉴权闭环。*

1. **后端 API 开发**：
    * `POST /api/auth/register`: 密码使用 `werkzeug.security` 进行 Hash 加密。
    * `POST /api/auth/login`: 校验密码，签发 JWT Token。
2. **前端页面与逻辑**：
    * 开发登录/注册 UI。
    * 在 Pinia 中创建 `userStore`，保存用户信息和 Token。
    * 配置 Axios 请求拦截器（请求头自动带上 `Authorization: Bearer <token>`）。
    * 配置 Vue Router 路由守卫，未登录不可访问交易和发布页面。

---

## 阶段三：商品展示与管理闭环

*目标：实现商品的发布、查看、搜索和删除。*

1. **图片上传处理（本地化降级方案）**：
    * *先做本地存储。*
    * **后端**：写一个上传接口，接收文件并保存在本地项目的 `static/uploads` 文件夹中，返回本地 URL（如 `http://localhost:5000/static/uploads/xxx.jpg`）。
2. **后端 API 开发**：
    * `POST /api/products`: 接收商品信息并存库。
    * `GET /api/products`: 商品列表，支持 `?keyword=xx` 进行标题模糊查询（SQL `LIKE`）。
    * `DELETE /api/products/<id>`: 删除商品（需校验当前操作者必须是 `seller_id`）。
3. **前端页面与逻辑**：
    * **首页**：商品列表流式布局，顶部增加搜索框。
    * **发布页**：表单页面，支持图片上传和预览。
    * **商品详情页**：展示大图、价格、卖家信息，以及“删除”按钮（仅卖家可见）和“联系卖家/购买”按钮（买家可见）。

---

## 阶段四：购物与历史记录追踪

*目标：走通交易流水，用户能看到自己买的、卖的。*

1. **后端 API 开发**：
    * `POST /api/orders`: 创建订单。**关键逻辑**：使用数据库事务（Transaction），将订单插入 Order 表的同时，将对应 Product 的状态改为“已售”。
    * `GET /api/users/me/published`: 获取我发布的商品历史。
    * `GET /api/users/me/bought`: 获取我购买的订单历史。
2. **前端页面与逻辑**：
    * **商品详情页**：点击“购买”触发 API，成功后跳转结果页或回首页。
    * **个人中心页 (我的)**：分两个 Tab 页面：“我发布的”和“我购买的”。

---

## 阶段五：卖家与买家实时交流

*目标：不刷新页面即可实现实时聊天。基于 WebSocket 实现。*

1. **后端 (Flask-SocketIO)**：
    * 初始化 SocketIO 并配置 CORS。
    * **认证**：客户端连接 WebSocket 时需携带 JWT Token 进行身份验证。
    * **事件监听**：
        * `on('connect')`: 记录用户上线（可将用户 ID 和当前 Socket Session ID 关联存入内存字典或 Redis）。
        * `on('send_message')`: 接收前端发来的消息 -> 存入 `Message` 数据库表 -> 查找接收方是否在线 -> 若在线，通过 `emit('receive_message')` 推送给对方。
    * `GET /api/messages/history/<contact_id>`: 提供一个 RESTful 接口拉取与某人的历史聊天记录。
2. **前端 (socket.io-client)**：
    * 在 Pinia 中建立 `chatStore` 管理 WebSocket 连接状态和消息列表。
    * **聊天界面**：左侧联系人列表，右侧聊天窗口。
    * 打开聊天窗口时，先请求历史记录接口渲染屏幕，随后监听 `receive_message` 事件，新消息 push 到数组中触发 Vue 视图更新。

## 阶段六：联调、测试与优化

*目标：修复 Bug，提升体验，准备本地展示。*

1. **权限越权测试**：尝试用 User A 的 Token 去调用删除 User B 商品的接口，确保后端有严格拦截。
2. **UI 细节优化**：补充商品卖出后的“已售罄”遮罩层；优化聊天界面的气泡样式和滚动条自动触底。
3. **本地演示准备**：
    * 准备几个测试账号（User A 扮演卖家，User B 扮演买家）。
    * 准备一批清晰的商品图片填充数据库，让首页（样机展示页）看起来丰满。

## 重点技术指南

1. **跨域问题 (CORS)**：本地开发时 Vue 跑在 `localhost:3000` (或 5173)，Flask 跑在 `localhost:5000`。后端务必配置 `Flask-CORS`，否则前端 API 全报错。SocketIO 实例化时也要加上 `cors_allowed_origins="*"`。
2. **Vue3 响应式丢失**：在使用 Pinia 和 Vue Router 时，解构赋值容易导致响应式丢失，尽量使用 `storeToRefs`。
3. **图片本地存储**：后端一定要做静态目录映射。在 Flask 中：

    ```python
    app = Flask(__name__, static_folder='static', static_url_path='/static')
    ```

4. **订单状态一致性**：下单操作（扣减商品状态，生成订单）必须放在 ORM 的**事务**里：

    ```python
    try:
        # 创建订单
        # 更改商品状态
        db.session.commit()
    except Exception:
        db.session.rollback()
    ```
