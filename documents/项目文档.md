# 东南大学二手交易平台 - 开发文档 (v1.0)

---

## 1. 技术栈概述

* **前端**：Vue 3 (Composition API) + Vite + Pinia (状态管理) + Vue Router + Element Plus (UI组件库) + Axios。
* **后端**：Python 3.14 + Flask 3.x + Flask-SQLAlchemy (ORM) + Flask-JWT-Extended (鉴权) + PyMySQL。
* **数据库**：MySQL 8.0 (字符集 `utf8mb4`)。
* **架构**：前后端分离 (RESTful API JSON 交互)。
* **实时通讯**：`Flask-SocketIO` (后端，基于 `gevent` 异步并发) + `socket.io-client` (前端)。全局长连接维持，支持跨组件消息弹窗。

---

## 2. 全局设计规范

### 2.1 UI/UX 色彩规范 (基于东南大学 VIS)

前端全局样式已在 `src/style.css` 中定义为 CSS 变量，后续开发禁止使用硬编码颜色，统一使用以下变量：

* **标准主色**：
  * 东南绿: `var(--seu-green)` -> `#587558` (用于系统主色调、主要按钮、激活状态)
  * 东南黄: `var(--seu-yellow)` -> `#fdd000` (用于点缀、强调)
  * 标准黑: `var(--seu-black)` -> `#231815` (用于深色背景、阴影)
* **标准辅助色**：
  * 活力橙: `var(--seu-orange)` -> `#F6AB00` (用于警告、次要操作如“注册”按钮)
  * 深邃蓝: `var(--seu-dark-blue)` -> `#151E49` (用于大面积背景、Banner)
* **排版风格**：**现代扁平极简风**。去除不必要的边框，多留白，利用投影(`box-shadow`)区分层级。

### 2.2 后端 API 响应规范

所有接口的返回格式必须统一为 JSON。

* **成功响应 (HTTP 200/201)**：包含 `msg` (提示信息) 和可选的 `data` / 具体字段。
* **失败响应 (HTTP 400/401/403/500)**：必须包含 `msg` 字段，前端 Axios 拦截器会**自动提取 `msg` 并通过 Element Plus 全局弹窗报错**，无需前端在业务代码中重复写 `catch` 弹窗。

## 3. 前端开发规范

### 3.1 目录职责划分

* `src/api/`: 所有后端接口必须在此目录下集中声明并导出，**严禁在 .vue 文件中直接写 axios.get(...)**。
* `src/stores/`: 全局状态管理。使用组合式 API 编写 Pinia store。
* `src/views/`: 页面级组件（如首页、商品详情页）。
* `src/components/`: 可复用的颗粒化 UI 组件（如商品卡片 `ProductCard.vue`）。

### 3.2 鉴权与路由拦截

* **Token 注入**：`src/api/request.js` 已配置请求拦截器。发起网络请求时，会自动在请求头携带：`Authorization: Bearer <token>`。
* **页面鉴权**：在 `src/router/index.js` 中，如果页面需要登录才能访问，必须在其路由配置中添加 `meta: { requiresAuth: true }`。

---

## 4. 后端开发规范

### 4.1 目录职责划分

采用**应用工厂模式 (Application Factory)** 防止循环引用。

* `app/models.py`: 数据库 ORM 映射。所有 SQL 操作必须通过 SQLAlchemy 执行，防止 SQL 注入。
* `app/api/`: API 蓝图 (Blueprints) 目录。按业务划分文件（如 `auth.py`, `product.py`, `order.py`）。
* `app/extensions.py`: 存放实例化的第三方扩展 (`db`, `jwt` 等)。

### 4.2 数据库操作规范 (ORM)

* 所有涉及写入、更新、删除的操作，必须使用 `try...except` 包裹，并在 `except` 中执行 `db.session.rollback()` 以保证事务原子性。

### 4.3 静态资源与图片上传规范

* 图片上传一律保存在后端的 `static/uploads/` 目录下。
* **防路径穿越与重名**：禁止直接使用用户上传的文件名，必须在接收文件后提取后缀，并使用 `uuid.uuid4().hex` 重新生成文件名。
* **前端访问**：上传成功后，数据库与接口返回的是完整的 URL 路径（如 `http://localhost:5000/static/uploads/xxx.jpg`）。

### 4.4 数据库删除规范（软删除）

* 由于存在交易流水（Order 表），严禁对已产生的商品（Product）进行物理删除（`db.session.delete()`）。
* 删除操作必须采用**逻辑删除（软删除）**，即通过修改状态机实现：将 `status` 字段修改为 `'deleted'`。

## 5. API 接口文档 (鉴权模块)

### 5.1 用户注册

* **路径**：`POST /api/auth/register`
* **权限**：公开访问
* **请求 Body (JSON)**：

    ```json
    {
      "username": "SEU小明",
      "email": "xiaoming@seu.edu.cn",
      "password": "your_password"
    }
    ```

* **成功响应 (201 Created)**：

    ```json
    { "msg": "注册成功" }
    ```

* **失败响应 (400 Bad Request)**：

    ```json
    { "msg": "该邮箱或用户名已被注册" }
    ```

### 5.2 用户登录

* **路径**：`POST /api/auth/login`
* **权限**：公开访问
* **请求 Body (JSON)**：

    ```json
    {
      "email": "xiaoming@seu.edu.cn",
      "password": "your_password"
    }
    ```

* **成功响应 (200 OK)**：

    ```json
    {
      "msg": "登录成功",
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
      "user": {
        "id": 1,
        "username": "SEU小明",
        "email": "xiaoming@seu.edu.cn"
      }
    }
    ```

    *(注：前端接收到此响应后，会自动将 token 存入 LocalStorage 和 Pinia 中)*

### 5.3 发布商品 (包含图片上传)

* **路径**：`POST /api/products`
* **权限**：需 Header 携带 Token (`Authorization: Bearer <token>`)
* **Content-Type**：`multipart/form-data` **(前端必须使用 FormData 对象，不能用 JSON)**
* **请求参数 (FormData)**：
  * `title` (String): 商品标题 (必填)
  * `price` (Numeric): 商品价格 (必填)
  * `description` (String): 商品描述 (可选)
  * `image` (File): 图片二进制文件，支持 png, jpg, jpeg, gif (可选)
* **成功响应 (201 Created)**：

    ```json
    {
      "msg": "商品发布成功",
      "data": {
        "id": 10,
        "seller_name": "SEU小明",
        "title": "二手高数教材",
        "price": 15.50,
        "image_url": "http://localhost:5000/static/uploads/abcd...1234.jpg",
        "status": "active",
        "created_at": "2023-10-25 10:00:00"
      }
    }
    ```

### 5.4 获取商品列表 (支持模糊搜索)

* **路径**：`GET /api/products`
* **权限**：公开访问
* **Query Params**：
  * `keyword` (String, 可选): 搜索关键字，匹配标题。例：`/api/products?keyword=高数`
* **成功响应 (200 OK)**：

    ```json
    {
      "msg": "获取成功",
      "data": [
        {
          "id": 10,
          "seller_name": "SEU小明",
          "title": "二手高数教材",
          "price": 15.50,
          "image_url": "http://localhost:5000/static/uploads/abcd...1234.jpg",
          "status": "active",
          "created_at": "2023-10-25 10:00:00"
        }
      ]
    }
    ```

### 5.5 获取商品详情

* **路径**：`GET /api/products/<int:id>`
* **权限**：公开访问
* **成功响应 (200 OK)**：返回单个商品的详细数据 (同上商品对象格式)。
* **失败响应 (404 Not Found)**：若商品状态为 `deleted`，返回 `{"msg": "该商品已下架"}`。

### 5.6 删除商品

* **路径**：`DELETE /api/products/<int:product_id>`
* **权限**：需 Header 携带 Token，**且操作者必须是商品的卖家 (seller_id)**
* **成功响应 (200 OK)**：

    ```json
    { "msg": "商品删除成功" }
    ```

* **失败响应 (403 Forbidden)**：

    ```json
    { "msg": "无权操作他人的商品" }
    ```

### 5.7 创建订单 (立即购买)

* **路径**：`POST /api/orders`
* **权限**：需 Header 携带 Token
* **请求 Body (JSON)**：

    ```json
    { "product_id": 10 }
    ```

* **成功响应 (201 Created)**：

    ```json
    {
      "msg": "购买成功",
      "data": {
        "order_id": 1,
        "order_no": "20231026123000A1B2C3D4",
        "deal_price": 15.50
      }
    }
    ```

* **失败响应 (400 Bad Request)**：触发防超卖锁或异常状态拦截。

    ```json
    { "msg": "手慢了，该商品已被抢购" } // 或 "不能购买自己发布的商品"
    ```

### 5.8 获取我发布的商品历史

* **路径**：`GET /api/users/me/published`
* **权限**：需 Header 携带 Token
* **成功响应 (200 OK)**：返回当前用户发布的所有商品（包含下架和已售，用于个人中心展示）。

    ```json
    {
      "msg": "获取发布历史成功",
      "data": [
        {
          "id": 10,
          "title": "二手高数教材",
          "price": 15.50,
          "image_url": "http://...",
          "status": "sold",
          "created_at": "2023-10-25 10:00:00"
        }
      ]
    }
    ```

### 5.9 获取我购买的订单历史

* **路径**：`GET /api/users/me/bought`
* **权限**：需 Header 携带 Token
* **成功响应 (200 OK)**：返回当前用户作为买家的所有订单流水，并关联商品与卖家信息。

    ```json
    {
      "msg": "获取购买历史成功",
      "data": [
        {
          "order_id": 1,
          "order_no": "20231026123000A1B2C3D4",
          "deal_price": 15.50,
          "order_status": "completed",
          "order_time": "2023-10-26 12:30:00",
          "product": {
            "id": 10,
            "title": "二手高数教材",
            "image_url": "http://...",
            "seller_name": "SEU小明"
          }
        }
      ]
    }
    ```

### 5.10 获取历史联系人列表

* **路径**：`GET /api/messages/contacts`
* **权限**：需 Header 携带 Token
* **成功响应 (200 OK)**：返回与当前用户有过聊天的联系人列表（按最后聊天时间倒序，包含未读数）。

    ```json
    {
      "msg": "获取联系人列表成功",
      "data": [
        {
          "id": 2,
          "username": "买家小李",
          "last_message": "这本教材还在吗？",
          "last_time": "2023-10-26 14:05:00",
          "unread_count": 1
        }
      ]
    }
    ```

### 5.11 获取与某人的历史记录

* **路径**：`GET /api/messages/history/<int:contact_id>`
* **权限**：需 Header 携带 Token
* **成功响应 (200 OK)**：获取对话记录，**并且后端会自动将对方发来的未读消息标记为已读**。

    ```json
    {
      "msg": "获取历史记录成功",
      "data": {
        "contact": { "id": 2, "username": "买家小李" },
        "messages": [
          {
            "id": 101,
            "sender_id": 2,
            "receiver_id": 1,
            "content": "这本教材还在吗？",
            "is_read": true,
            "created_at": "2023-10-26 14:05:00"
          }
        ]
      }
    }
    ```

## 6. 实时通讯 WebSocket 规范

### 6.1 鉴权与连接生命周期

* **全局连接**：前端在 `App.vue` 中监听全局 Token 变化。登录后自动发起 WebSocket 连接，退出登录后主动断开，确保任意页面均可接收消息弹窗通知。
* **握手鉴权**：客户端连接时必须通过 `auth: { token: "<JWT>" }` 传递凭证，后端通过 `decode_token` 手动解析并维护 `user_id <-> sid` 的内存字典映射。
* **多标签页防脑裂**：前端 `App.vue` 中配置了 `storage` 事件监听。若用户在多个浏览器标签页中切换登录账号，所有标签页会强制刷新并对齐 Socket 身份，防止越权发送。

### 6.2 Socket 核心事件字典

| 事件名称 | 发起方 | 数据载荷 (Payload) | 业务作用说明 |
| :--- | :--- | :--- | :--- |
| `send_message` | 前端 -> 后端 | `{ "receiver_id": 2, "content": "你好" }` | 客户端发送私信。后端接收后持久化入库，并查找接收方路由。 |
| `receive_message` | 后端 -> 前端 | `{ "id": 102, "sender_id": 1, "content": "你好" ... }` | 服务端推给接收方。若前端不在当前聊天界面，则触发全局弹窗通知。 |
| `mark_as_read` | 前端 -> 后端 | `{ "message_id": 102 }` | **消除幽灵未读机制**。前端判定当前正在活跃聊天窗口中收到新消息时，静默发送此回执，后端将其在数据库更新为已读状态。 |
| `error` | 后端 -> 前端 | `{ "msg": "发送失败..." }` | 统一异常回抛机制，前端捕获后通过 Element Plus 全局弹层报错。 |
